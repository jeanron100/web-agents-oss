# 容器开源交付进度与发布门槛

本轮已把私人部署改造成可初始化的交付候选版。目标用户是单管理员或可信小团队；原生 Linux 节点与容器节点使用独立执行环境。

## 已完成

| 范围 | 交付内容 |
|---|---|
| 可移植配置 | 空服务器模板；外部私有配置；账号映射、目录、监控和模型配置不依赖固定服务器 |
| 接入体验 | 初始化管理员、登录退出、密码修改；后端异常不再自动展示演示项目 |
| 多服务器 | 页面添加、编辑、测试、禁用、移除；独立令牌；节点身份、CLI 版本与凭据存在检测 |
| 容器 | 控制台、MySQL、可选非 root runner；独立状态/账号/工作区卷；健康检查；无宿主机 PID 或 Docker socket |
| 运维 | 一键初始化、诊断、带校验和的备份恢复；原生与容器 CLI 生命周期说明 |
| MCP | 独立只读凭据；8 个工具；节点查询、进展与原文证据接入说明 |
| 发行 | 干净导出清单与 SHA-256；ISC；贡献和安全说明；CI 与手动镜像发布工作流 |

## 已实际验证

- Linux amd64 两个镜像构建成功，独立 Compose 安装的控制台、MySQL、runner 均健康。
- Codex 0.159.2：app-server 握手及外部容器沙箱内的一次本地命令；Kimi Code 2.2.0：ACP 握手。Claude 2.1.301：可执行文件版本检测。
- 管理员初始化/登录、受保护 API、跨站拒绝、令牌不回显、节点增删改与禁用。
- 真实浏览器检查 1440、390、320 宽度，验证登录、节点表单与操作；无横向溢出或脚本错误。
- stdio MCP 列出 8 个工具并查询真实测试节点；匿名终端连接被拒绝，登录后 WebSocket 能经节点鉴权往返执行命令。
- MySQL 测试记录备份后删除，再恢复并读回；管理员和节点配置在控制台重启后保留。
- 干净导出包后端测试 935 项通过、11 项跳过；前端 234 项通过；增量安全/容器修复另有针对性回归。跳过项涉及未启用的可选集成，不能视为这些服务已验收。
- 当前导出扫描未发现非测试凭据匹配；私人旧 Git 历史仍有历史认证值，未重写或公开。

这些验证没有登录厂商账号，也没有替代真实模型任务验收。测试镜像保存在隔离环境中，未向公共注册表推送；未迁移现有生产 CLI。

## 首次正式公开前仍需完成

1. **真实任务验收**：用户在隔离 runner 登录 Codex/Kimi，执行编辑、命令、补充/排队、审批、中断、恢复和图片输入；核对账号权限及 CLI 版本兼容。检测到凭据文件不能替代认证成功。
2. **发布合规与供应链**：核对第三方 CLI/SDK 的镜像再分发许可、漏洞与依赖清单；固定发布镜像及摘要。源码 ISC 不覆盖第三方软件。
3. **公开入口**：确定新公开仓库、注册表、首个版本与私密漏洞报告入口，启用手动发布环境保护。只能公开干净导出，不直接公开私人 Git 历史；若保留旧历史，必须先清理并轮换关联凭据。

## 后续优先级

P1 优先补节点向导中的 CLI 登录状态实测、版本兼容矩阵、可视化升级/回滚、备份恢复状态和持续故障提示。先证明陌生用户从安装到第一个真实任务都能完成，再增加引擎数量。

P2 再评估多用户/RBAC、项目级隔离、配额与成本策略、通知渠道扩展，以及更轻的单节点存储方案。当前不应以“支持多服务器”宣称已具备多租户安全隔离。
